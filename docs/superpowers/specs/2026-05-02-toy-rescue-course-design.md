# おもちゃレスキューコース 3Dゲーム設計

## 要件台帳

| ID | 状態 | 要件 | 理由・補足 |
| --- | --- | --- | --- |
| REQ-001 | 維持 | 救急車やパトカーを操作できる | 最初の中核体験。 |
| REQ-002 | 維持 | 積み木にぶつかると積み木が倒れる | 物理演算の手触りを出す。 |
| REQ-003 | 維持 | 色付きプールに入ると一定時間だけ車体色が変わる | 色替え遊びの主ギミック。 |
| REQ-004 | 維持 | 色付きシャワーを浴びると一定時間だけ車体色が変わる | プールと違う通過ギミックにする。 |
| REQ-005 | 維持 | 机上のおもちゃコース風の3Dゲームにする | 添付画像の世界観を独自に再構成する。 |
| REQ-006 | 追加 | 消防車、ブルドーザー、ショベルカーなど複数の働くくるまを選べる | 車種選択の楽しさを増やす。MVPでは見た目と操作パラメータを変える。 |

## 要件差分

| 区分 | 要件 | 影響 |
| --- | --- | --- |
| 維持 | REQ-001〜REQ-005 | R3F + Rapier の3D物理ゲームとして実装する。 |
| 追加 | REQ-006 | 車種データ、車両切り替えHUD、車種別パラメータが必要。 |
| 保留 | ミッション、スコア、ステージ選択 | MVP後に追加する方が操作と物理の確認を優先できる。 |
| 削除 | なし | 現時点では削除しない。 |

## 方針

React Three Fiber を使い、Canvas内は3Dプレイフィールド、HUDはReact DOM overlayに分ける。物理は `@react-three/rapier` に任せ、車体・積み木・床・境界を剛体として扱う。ゲーム状態のうち車種、色効果、入力状態、リセット要求はReact側で管理し、高頻度の位置更新はR3F/Rapier側で扱う。

## 世界観辞書

- 床: 明るい木目の机。
- 車: 丸みのある働くくるまのおもちゃ。救急車、パトカー、消防車、ブルドーザー、ショベルカー。
- 積み木: 赤、青、黄、緑、木目の角丸ブロック。
- 色プール: 半透明の絵の具だまり。
- 色シャワー: 上から落ちる色粒と柱状のトリガー。
- HUD: 大きいアイコン風ボタン、短い日本語ラベル、操作中の視界を邪魔しない配置。

## 車種

| 車種 | 見た目 | 操作差 |
| --- | --- | --- |
| 救急車 | 白地、赤ライン、赤色灯 | 標準速度、旋回しやすい。 |
| パトカー | 白黒、赤青ライト | 速い、少し軽い。 |
| 消防車 | 赤い長めの車体、白いはしご | 重め、押す力が強い。 |
| ブルドーザー | 黄色、前面ブレード | 遅い、積み木を押しやすい。 |
| ショベルカー | オレンジ、アームとバケット | 遅め、旋回強め。 |

## 受け入れ条件

- キーボードまたは画面上の操作ボタンで車を前後左右に動かせる。
- 車種ボタンで5種類の働くくるまを切り替えられる。
- 車が積み木に当たると、積み木が倒れたり押されたりする。
- 赤、青、黄のプールまたはシャワーに触れると車体色が変わり、数秒後に元へ戻る。
- Desktop 1280x720、tablet portrait 768x1024、mobile portrait 390x844でHUDが主要オブジェクトに重ならない。
- `window.render_game_to_text()` で現在車種、色効果、位置、積み木数を確認できる。

## 非対象

- YouTube動画の映像、音声、固有表現のコピー。
- 本格的な車両モデルやGLB制作。
- ミッション、スコア、セーブ、ステージ選択。
- マルチプレイ。

## リスクと対策

- 物理が暴れる: MVPでは積み木数を抑え、車速と質量を控えめにする。
- モバイルHUDが視界を塞ぐ: 下部操作エリアを半透明にし、カメラターゲットを少し上へ寄せる。
- React state更新が多すぎる: 位置や速度の高頻度更新はrefsとRapier APIで扱い、HUD同期は間引く。
- 色効果と車種切り替えが競合する: 車種の基本色と一時色を別状態として管理する。

## 性能目標

- Desktop: 60fps目標。
- Mobile: 30fps以上。
- 初期積み木は40個前後まで。
