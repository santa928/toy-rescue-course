# 地区床・街角装飾拡充 設計

**日付:** 2026-08-02

**状態:** 設計承認済み・実装未着手

**対象:** 7地区の床色・模様、入口サイン、街角装飾、物理、telemetry、3 viewport、性能再認証

## 1. 目的

96×96箱庭の広い木色床が連続し、ランドマークがカメラ外へ出ると現在地を見失う問題を解消する。7地区へ固有の床色・模様と、道路端の街角装飾を追加し、文字やミニマップへ頼らず「色と形」で場所を判断できる街にする。

既存の道路幅、15仕事、車両物理、仕事座標、自由走行、色遊び、積み木破壊、カメラ、HUDは変更しない。肌色の木床は箱庭の外周と地区間の余白に残し、「木の机へ広げた玩具セット」という世界観を維持する。

## 4. 比較案と採用判断

### A. 地区カーペット

地区全体を大きな色面で分ける。最も迷いにくいが、装飾が少なくボードゲーム盤に見えやすい。

### B. 道路と入口で案内

木床を広く残し、色付き路肩、横断模様、門、標識で方向を示す。机上玩具らしさは強いが、道路外で木色床問題が残る。

### C. 地区床＋街角セット（採用）

地区固有の薄い床・模様と、道路端の街角装飾を組み合わせる。色と形の両方で現在地を判断でき、中央の走行空間も維持できる。ユーザー選択によりCを採用する。

## 5. データ境界

`ProductionWorldMapDefinition`へ次の独立した静的層を追加する。

- `surfaceTiles`: `id`、`districtId`、`color`、`position`、`scale`を持つ。全要素を非solidとし、道路面より低い位置へ置く。
- `decorationClusters`: `id`、`districtId`、用途、複数のboxを持つ。boxごとに`solid`を明示する。

既存`visualBoxes`の建物・木・標識・車庫等は互換性のため維持する。既存の`park-ground`、`block-plaza-ground`、`construction-ground`、`town-green-west`、`town-green-east`は同じIDとanchorを保ったまま`surfaceTiles`へ移し、承認paletteと道路より低い高さへ統一する。これにより肌色の旧工事床や高い床プレートを新床と二重表示しない。

描画時は既存boxと新装飾boxを同じ色別batchへまとめる。新しい床層はper-instance colorを持つ単一`InstancedMesh`で描き、地区色や模様の数をdraw callへ比例させない。

物理は既存solidと新装飾の`solid: true`だけを、単一fixed `RigidBody`配下の`CuboidCollider`へ変換する。床や非solid装飾からcolliderを作らない。React state、毎frameの配列生成、Three.js object生成、asset fetchは追加しない。

`render_game_to_text()`のworld情報へ、`surfaceTileCount`、`decorationClusterCount`、`decorationBoxCount`、`staticColliderCount`を追加する。現在地区は既存telemetryを維持し、HUDへ地区名を追加しない。

## 6. 配置とアンカー

地区床は各district boundsを基準にし、道路より低い一枚の基底タイルと、4unit以上の間隔を持つ模様タイルで構成する。道路が上から覆うため、床が道路線や交差点を隠さない。

新規街角装飾群は次の最終密度とする。

| 地区 | 装飾群数 | 構成 |
| --- | ---: | --- |
| 中央車庫 | 2 | 荷物箱＋工具棚、赤白案内ブロック |
| 公園 | 3 | 花壇＋ベンチ、街灯＋生垣、ピクニック卓 |
| 火災地区 | 3 | 消火栓＋街灯、植木鉢、郵便箱＋歩道模様 |
| 積み木広場 | 3 | 入口コーン＋柵、パレット、工具箱＋案内板 |
| 南地区 | 3 | 入口旗、観覧ベンチ、色遊び外周の低い花壇 |
| こうじヤード | 3 | 入口バリケード、資材＋工具箱、作業灯 |
| おもちゃのまち | 4 | 西街灯、東街灯、ベンチ＋生垣、郵便箱＋玄関模様 |

solid追加は最大13 boxとし、既存27個と合わせて40以下にする。solidは道路boxを車体半幅相当の1.6unitだけ拡張した領域へ侵入させない。車庫入口、仕事対象、色遊びtriggerの追加安全余白は各既存判定範囲の外側へ1.5unit確保する。既存の仕事定義validatorでも、新solidと実targetの距離を検証して循環依存を作らない。

床・模様・花・コーン・看板板・旗布・生垣の葉は非solidとする。街灯柱、ベンチ本体、柵支柱、消火栓、大きなバリケード支柱はsolidとする。見た目のないcollider、薄い模様への衝突、装飾の間を塞ぐ連続壁は作らない。

## 7. UIアンカー

HUDの位置と文言は変更しない。地区床・入口サイン・街角装飾は追従カメラ内のworld objectであり、画面比率で配置しない。

Desktop 1280×720、Tablet 1024×768、Mobile landscape 844×390で、各地区の代表地点へ車両を置いたとき次を満たす。

- 固有床色または模様が車両周囲に見える。
- 入口または街角装飾が最低1群見える。
- mission、selector、fullscreen、audio、joystick、主操作の下へ重要ランドマークを意図的に隠さない。
- 操作系とCanvas四辺の既存安全余白を維持する。

## 8. Validationと失敗時契約

pure validatorは次をID付きのエラーとして拒否する。

- surface／cluster／boxの重複ID、非finite座標、非正寸法、world外配置。
- surfaceの地区外配置、道路面以上の高さ、地区ごとの道路外被覆率70%未満。
- decoration clusterの地区外配置、2未満または4超の群数。
- 新solidの道路拡張領域、車庫入口、色遊びtriggerへの侵入。
- 新solidと仕事targetの安全距離違反。
- 新規色がsurfaceのper-instance colorまたは既存装飾paletteへ収まらず、draw call上限を越える構成。

不正定義を黙って非表示にしたり非solidへ変更したりせず、起動guardまたはテストで対象IDと理由を明示する。

## 9. 性能目標

- surfaceは1 draw call。
- decorationは既存palette batchへ統合し、新規draw call 2以下。
- 完成sceneは車種を問わず34 calls以下。
- static colliderは40以下、fixed bodyは1。
- game entry 350kB、通常chunk 600kB、Three 750kB、Rapier 2.25MB以内。
- 毎frame React state更新0、追加asset fetch 0。
- Apple M4 1280×720で全5車種median 55fps以上、p10 45fps以上。

性能未達時はsurfaceのbatch統合、装飾box削減、solid数削減の順で対処する。world boundsは96×96のままなので、chunk streaming／LODは追加しない。

## 10. 検証

### Unit／build

- surface、cluster、coverage、安全余白、ID、palette、collider上限のpure test。
- `VoxelWorld`がsurfaceを1 batch、装飾を既存色batch、全solidを1 fixed bodyへ接続するrender test。
- fresh full unitとPages base付きbudget build。

### 実ブラウザ

- 7地区をDesktop keyboard、Tablet touch、Mobile landscape touchで実走する。
- 各地区の入口、中心、別出口と、追加solid 1件以上への衝突、非solid 1件以上の通過を確認する。
- 15仕事、帰庫、乗り換え、色遊び、積み木破壊、既存solid collisionを回帰する。
- `render_game_to_text()`の地区、surface／decoration／collider countと実描画を一致させる。
- 7地区×3 viewportの21画像を原寸目視し、広い木色面、見切れ、HUD重なり、装飾による操作阻害がないことを確認する。
- console、page、request error 0とproduction smoke 3入口を確認する。
- Apple M4物理GPUで5車種のmedian、p10、scene／vehicle callsを再測定する。

## 11. リスクと対策

| リスク | 対策 |
| --- | --- |
| 地区色が強く車両や対象を埋もれさせる | 彩度を車両より一段下げ、道路と仕事対象の既存高彩度を優先する。 |
| 床と道路がちらつく | surface上面を道路上面より下げ、同一平面を重ねない。 |
| 装飾で既存経路を塞ぐ | expanded road、仕事target、triggerのpure safety validationと実走E2Eを両方行う。 |
| collider増加で走行や性能が悪化する | 追加13、合計40の上限を固定し、Apple M4で再認証する。 |
| 色数でdraw callが増える | surfaceをinstance color 1 batch、装飾を既存paletteへ限定する。 |
| 地区内でもカメラ方向によって目印が消える | 2〜4群を対角へ分散し、3 viewportの代表方向を21画像で目視する。 |

## 12. 非対象

- 新しい仕事、NPC、交通、歩行者、6台目の車両。
- ミニマップ、地区名HUD、ナビ矢印、設定画面。
- 昼夜、天候、影品質変更、高低差、坂、地形変形。
- 壊せる街灯、建物、ベンチ、柵。
- 96×96を超える拡張、非同期load、chunk streaming、LOD。
- 写実的テクスチャ、透明床、流体、外部3D／画像asset。
