# おしごと案内・ミニマップ改善 設計

**日付:** 2026-08-02

**状態:** 実装・ローカル検証完了（GitHub Issue #1）

## 1. 目的

パトカー、ショベルカー、ブルドーザーを中心に、仕事名だけでは「何へ」「どの操作で」「何個できればクリアか」が分からない問題を解消する。消防車を含む全5車種へ同じ案内構造を適用し、仕事完了後は中央車庫へ戻れば次の仕事と炎が再開することも画面内で伝える。

## 2. 世界観辞書

共通語彙は「木の机、玩具の街、道路標識、働く車の固有色」とする。仕事札は道路標識、ミニマップは車載の紙地図、目的地は黄色い丸ピン、現在地は選択車両色の小さな車として表す。写実的なGPS、衛星地図、複雑な凡例、細い文字は使わない。

## 4. データと状態

`buildMissionGuidance()`を唯一の変換境界とし、coordinator snapshotから次を生成する。

- `instructionLabel`: 車種固有の対象と操作。
- `completionLabel`: `クリア 現在/目標`。
- `targetLabel`: 火、次のがれき、次の土、けがをした人、次のゲート、中央車庫。
- `targetPosition`: 定義順で最初の未完了対象。完了後は中央車庫。

HUDと`render_game_to_text().mission.guidance`は同じ値を読む。対象完了時はruntimeの完了IDを使って次ピンへ進み、仕事定義と別の座標表を持たない。

## 5. UIアンカー

仕事札は画面上中央を維持し、仕事名、具体操作、巡回・達成数の順に表示する。ミニマップは右上の全画面・音ボタン列へアンカーし、音ボタン下へ8px以上の間隔で置く。現在地と対象はマップboard内へ収める。

Desktop 1280×720、Tablet 1024×768、Mobile landscape 844×390では、selector、仕事札、全画面、音、ミニマップ、レバー、主操作の全組を8px以上離す。狭い縦画面でselectorが全幅になる場合は、ミニマップをselector下へ移す。

## 6. 性能目標

- 毎frame React state更新0。
- 追加Three draw call 0、Rapier body／collider 0、asset fetch 0。
- game entry 350kB、通常chunk 600kB、Three 750kB、Rapier 2.25MB以内。
- CSS marker更新は1 animation frameにつき現在地の`left/top`と距離文字だけ。

## 7. リスクと対策

| リスク | 対策 |
| --- | --- |
| 小型マップが既存HUDや主操作へ重なる | pure矩形helperと3 viewportの実寸E2Eで安全余白を検証する。 |
| 対象完了後も古いピンが残る | runtime完了IDとcurrent jobから毎回次対象を導出するunit testを持つ。 |
| 仕事札が長く車両を隠す | 一行省略と既存最大幅を維持し、具体操作を短い平仮名中心にする。 |
| 現在地更新でReactが高頻度再描画される | telemetry refを直接読み、marker DOMだけを更新する。 |
| 消防2周目の炎がないように見える | 完了後は車庫ピンを出し、帰庫後のfire intensity 1、18 voxel、次jobを既存2周E2Eで再確認する。 |

## 8. 非対象

- 音声ナビ、ルート再探索、回転する地図、ズーム、地図操作。
- 新しい仕事、仕事数、対象座標、クリア判定、車両物理の変更。
- 地区名の常時表示、設定画面、チュートリアルモーダル。

## 9. 検証

- guidance、未完了ターゲット、車庫切替、座標投影のpure unit。
- HUD文言、ARIA、マップmarkerのSSR test。
- HUD矩形、board内markerのpure／runtime数値検証。
- 追加3車種の仕事完了・帰庫・次仕事を3 viewportで実走し、マップと案内を確認する。
- 消防車を2周し、各周の炎、案内、車庫帰還、次jobを確認する。
- 代表画像を原寸目視し、重なり、はみ出し、操作阻害、読めない文字がないことを確認する。

### 実測結果

- unit test: 48 files / 463 tests成功。
- production build: 660 modules、game entry 161,648 bytes。全chunk budget成功。
- ショベルカー・救急車・パトカー: Desktop 1280×720、Tablet 1024×768、Mobile landscape 844×390で、仕事完了、帰庫、次仕事、HUD 8px安全余白、markerのboard内収まりを確認。
- 消防車: keyboard／touchを含む3 viewportで異なる2仕事を完了し、各帰庫後に次jobとfire intensity 1が復帰することを確認。
- 代表画像を原寸目視し、仕事札、ミニマップ、車両、対象、操作UIに重なり・はみ出し・操作阻害がないことを確認。Mobile landscapeのパトカーmap captionは`つぎの ゲート`へ短縮し、全文表示を確認。
