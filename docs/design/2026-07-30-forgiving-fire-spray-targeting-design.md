# 消火放水の寛容な照準判定 設計書

## 目的

消防車の水が画面上では炎へ届いて見えるのに、消火判定へ入らない状態を解消する。
幼児でも「炎の近くでおおむね正面を向いて放水すれば消せる」操作感にしつつ、
背後や明確な範囲外からの放水は成功させない。

本設計は、72×72前後の本番マップ拡張に入る前の独立修正である。
消火判定と対象時の水流終点だけを変更し、炎・水の造形やanimation、ミッション進行、
車両、物理、HUDは変更しない。

## 現状と原因

現在の`resolveSprayTarget`は、車両ノズルから`FIRE_POSITION`への3次元距離が6unit以内、
かつ前方ベクトルとの内積が0.67以上、すなわち正面から約48度以内の場合だけ命中とする。

一方、`FIRE_POSITION`は建物内側の代表点`[12, 1.2, -11]`であり、画面に見える炎は
おおむね`[12.9, 0.75〜2.15, -9.1]`へ配置されている。判定点が見える炎より約1.9unit奥に
あるため、見た目では水が炎へ届いていても距離・角度の両方で対象外になりやすい。

## 採用する判定

### 照準点

消火判定と水流補正に使う座標を、建物内側の代表点から画面に見える炎の中心へ分離する。
照準点は`FIRE_SPRAY_TARGET_POSITION = [12.9, 1.45, -9.1]`としてworld layout上で定義し、
`WaterAndFire`が`resolveSprayTarget`へ明示的に渡す。

ミッションの目的地や建物配置に使う既存`FIRE_POSITION`は変更しない。
これにより、照準調整がroute、車庫、E2E移動経路へ波及しないようにする。

### 距離

判定距離はY軸の高低差を除いたXZ平面の水平距離で求め、7unit以内を対象にする。
地上車両の向き合わせへノズルと炎の高さ差を持ち込まない。

境界は7unitを含み、7unitを超える場合は対象外とする。非有限な入力は対象外とする。
`SprayTargetResult.distance`は水流の表示距離にも使うため、照準点までの3次元直線距離を
維持する。判定専用の水平距離とは意味を分ける。

### 前方角度

車両前方と照準点方向をXZ平面へ正規化し、内積0.5以上、すなわち正面から約60度以内を
対象にする。真横と背後は対象外とする。

ゼロ長または非有限な前方ベクトルは対象外とし、元の方向を維持する。

### 水流補正

対象内では、正規化した車両前方を45%、炎方向を55%として混合し、再正規化する。
判定だけ成功して水流が大きく外れて見える状態を減らしつつ、完全な自動照準にはしない。

対象外では従来どおり車両前方へ放水し、消火signalを発生させない。

### 水流の停止位置

既存の`WATER_TARGET_STOP_OFFSET = 1.9`は、建物内側の`FIRE_POSITION`から見える外壁面までの
奥行きを差し引く値だった。照準点を見える炎の中心へ移すため、この値を炎のcamera側外形に
合わせた0.55unitへ変更する。水流の形、instance数、速度は変更せず、対象時の終点だけを
見える炎の手前へ合わせる。

## 世界観辞書との整合

- 消防車: 承認済みの短く太い純ボクセル車両を維持する。
- 炎: 赤・橙・黄白の玩具ボクセル炎を維持する。
- 放水: 水色と白の流動的なボクセル列を維持する。
- 操作感: 精密射撃ではなく、働く車のおもちゃを動かして仕事を達成する手触りを優先する。
- HUD・文言: 操作可否と状態遷移は変わらないため、現行の放水ボタンと仕事案内を維持する。

## アーキテクチャと責務

```text
worldLayout
  ├─ FIRE_POSITION              # 建物・目的地の代表位置を維持
  └─ FIRE_SPRAY_TARGET_POSITION # 見える炎に対応する照準位置
             ↓
WaterAndFire
  ├─ ノズル位置・車両前方・照準位置をpure関数へ渡す
  └─ 水流終点を照準点の0.55unit手前へ合わせる
             ↓
sprayTargeting
  ├─ 水平距離
  ├─ 水平前方角度
  ├─ 対象内外
  └─ 55%方向補正
             ↓
VoxelGameRuntime
  └─ sprayOnFire=trueの時間だけ既存どおり消火を進める
```

`sprayTargeting`はReact、Three.js、Rapierへ依存しないpure domainとして維持する。
毎frameのReact state、Three.js object、物理bodyは追加せず、現在の固定O(1)計算量を維持する。

## データフロー

1. `WaterAndFire`が車両telemetryからノズル位置と前方を求める。
2. 見える炎に対応する照準位置を`resolveSprayTarget`へ渡す。
3. pure関数が水平距離と前方角度から`targeted`を決める。
4. `targeted=true`の場合だけ水流方向を55%補正し、`sprayOnFire=true`をruntimeへ渡す。
5. runtimeは既存どおり、有効放水が合計2.5秒続いた場合に消火を完了する。

## エラー処理

- 座標、距離、前方ベクトルのいずれかが非有限なら対象外とする。
- 前方ベクトルまたは照準方向の水平長が0なら対象外とする。
- 対象外では例外を投げず、元の前方方向と`targeted=false`を返す。
- 照準点の欠落を暗黙の`FIRE_POSITION`へフォールバックさせず、TypeScriptの必須引数で防ぐ。

## テスト方針

### Unit

- 見える炎の位置を基準に、水平7unit以内・前方60度以内が対象になる。
- 水平7unitを超える位置、60度を超える位置、真横、背後は対象外になる。
- ノズルと炎に高低差があっても、XZ条件が同じなら対象結果が変わらない。
- 対象内の補正方向は炎側へ寄り、長さ1へ正規化される。
- 非有限値とゼロ長前方は安全に対象外になる。

### Integration

- `resolveWaterAndFireFrame`が見える炎の照準位置を使って`sprayOnFire=true`を返す。
- 対象外の放水では`sprayOnFire=false`を維持する。
- 対象内の放水を2.5秒進めると、既存どおり`celebrating`へ遷移する。

### Browser E2E

- 現在より少し横へずれた位置から、炎をおおむね正面に捉えて消火できる。
- 同じ位置で炎を背後にした放水では火勢が減らない。
- 水流が炎側へ曲がり、消火中の飛沫が見える炎付近へ表示される。
- 対象時の水流が見える炎の中心より0.55unit手前で止まり、建物内側や大幅な手前で止まらない。
- Desktop 1280×720、tablet landscape 1024×768、mobile landscape 844×390で既存HUD、
  車両、炎、水の重なりやはみ出しが増えていない。

## 受け入れ条件

- 見える炎から水平7unit以内かつ前方約60度以内で放水すると、消火判定へ入る。
- 水流が炎方向へ補正され、判定成功時に明らかに逆方向へ飛ばない。
- 7unit超、約60度超、真横、背後では火勢が減らない。
- 有効放水2.5秒、成功演出、自由走行、帰庫再開が維持される。
- キーボードとタッチが同じ判定を使う。
- Unit、build、フルE2Eが成功し、console・page・request errorが0件である。
- 代表3 viewportのスクリーンショットを目視し、HUDと主要オブジェクトの安全余白を維持する。

## 非対象

- 72×72前後の本番マップ拡張。
- 追加車両、追加ミッション、ランダム火災。
- 消火時間2.5秒の短縮。
- 放水ボタン、仕事案内、HUDの変更。
- 水・炎VFXの造形、色、instance数、animation変更。水流終点の位置合わせだけは本修正に含む。
- 火災hazard collider、建物collider、車両物理の変更。
- 完全な自動照準、背後への追尾、画面外の火への追尾。
- セーブ、音、振動、進行、報酬。

## リスクと対策

| リスク | 対策 |
| --- | --- |
| 判定が広すぎて、炎を向いていなくても消える | 水平7unit・前方約60度へ限定し、真横・背後の負例を固定する。 |
| 判定だけ成功し、水が炎へ届いて見えない | 見える炎の照準点を共有し、方向を55%補正してE2E画像で確認する。 |
| 既存E2Eの移動経路が変わる | ミッション用`FIRE_POSITION`を維持し、照準点だけを分離する。 |
| 高低差を無視して不自然な遠距離照準になる | 距離はXZ、返す水流方向は3次元の炎方向を混ぜ、高さ方向の見た目は残す。 |
| 非有限telemetryでNaNが描画へ伝播する | pure関数で入力を検証し、対象外へ安全に倒す。 |

## 性能目標

- 照準判定は毎frame固定回数の算術演算だけで完了する。
- 毎frameのReact state更新、Three.js object生成、物理body追加を行わず、照準計算の
  allocation回数を現行より増やさない。
- 既存の物理GPU目標であるDesktop 60fps、tablet・mobile landscape 30fps以上を後退させない。
- Docker SwiftShaderのfpsは機能回帰の参考値に留め、物理GPU性能の認証には使わない。
