# 3歳児向けミッション視認性修正 設計

**日付:** 2026-08-03

**状態:** ユーザー承認済み・実装前

## 1. 目的

消防車の2件目・3件目を建物北面から見通しのよい屋外へ移し、3歳児が黄色い目印を理解できなくても、道路から玩具の炎そのものを発見できるようにする。

全15仕事を監査した結果、建物や大型物体の裏を意図的な正解地点にしていたのは`fire-window-left/right`だけだった。救急、ブルドーザー、ショベルカー、警察の12仕事は、進入路の終端から対象が見える道路、公園、広場にあり、配置を維持する。

## 2. 世界観辞書と配置原則

共通語彙は「木の机、玩具の街、地面の黄色い積み木道しるべ、赤橙黄の玩具の炎、短いひらがな仕事札」とする。

- 道しるべを追うと、最後の曲がり角より前から対象そのものが見える。
- 建物、大型遊具、樹木、塀の裏や袋小路を正解地点にしない。
- 黄色い立体マーカーとミニマップは発見の補助であり、遮蔽物の裏へ置く理由にしない。
- 炎、放水、成功星は既存の純ボクセル表現と固定poolを維持する。

主要オブジェクトとのアンカーは、地面ルートを走行可能な道路または開けた地区床へ置き、最後の2点を対象へ向く直線にする。対象と最後の案内区間の間へsolid boxを挟まない。

## 3. 採用する3つの消防仕事

| 仕事ID | 仕事札 | 対象 | 進入方向 |
| --- | --- | --- | --- |
| `fire-side` | よこの火をけそう | 既存建物の東側面 `[26.9, 1.45, -16.1]` | 東道路から既存位置へ接近 |
| `fire-hydrant` | しょうかせんのそばをけそう | 消防地区入口の消火栓東側 `[18.5, 1.45, -12]` | 開けた南側を通り東から西へ接近 |
| `fire-planter` | おはなのそばをけそう | 東側道路から見える花壇 `[25.5, 1.45, -8]` | 東道路から西へ接近 |

`fire-window-left/right`は仕事registryから削除する。建物北面の窓は街の装飾として残すが、ミッション対象には使わない。

## 5. 実装境界

- `vehicleJobs.ts`で2仕事のID、文言、target、12点route、成功星中心を屋外用へ置換する。
- `fire-route-plan.mjs`は建物北面という例外を削除し、既存建物側面と屋外東側接近の2パターンだけを扱う。
- `verify-voxel-game.mjs`はseed付き1巡の3仕事を完了し、2件目・3件目の発見時スクリーンショットを保存する。
- `WaterAndFire.tsx`の18炎slot、1 hazard collider、32水slot、12 route slot、6 marker slot、30成功星slotは増やさない。
- 新しい建物、道路、物理body、texture、audioは追加しない。

## 6. エラー処理と不変条件

- 消防仕事は3件、一意ID、fire地区内target、12個の有限route、6個の成功星を必須とする。
- 屋外2仕事の最後の2 routeは対象と同じZ上で、対象より東にあり、西へ進む順序にする。
- 屋外targetは既存solidとのjob clearance検証を通す。
- 別車種、成功演出、route非表示時は既存どおり炎と案内を切り替える。

## 7. 検証

- RED/GREEN unit: 新ID・文言・屋外target、東から西へ向く最後の2 route、北面route廃止。
- RED/GREEN Node test: `createFireRoutePlan`が2つの屋外仕事を実routeから解決し、建物裏のroute前提を持たない。
- Docker full Vitest、Node test、budget付きproduction build。
- Docker Playwright: keyboardとtouchで消防3仕事を1巡し、描画route由来の接近で全件完了する。
- Desktop 1280×720とMobile landscape 844×390で2件目・3件目の画像を原寸目視し、炎、対象マーカー、消防車、仕事札の欠落・遮蔽・重なりを確認する。
- `render_game_to_text`と画像でjob ID、target、route、console／page／request errorを照合する。

## 8. 性能目標

- 追加draw call 0、Rapier body／collider 0、asset fetch 0。
- 固定instance pool数と既存build budgetを維持する。
- 毎frame React state、配列、Three objectの追加生成0。

## 9. 非対象

- マップ拡張、道路・建物・装飾の追加。
- 消火時間、放水距離、自動追尾、車両速度・旋回、衝突判定の変更。
- 救急、ブルドーザー、ショベルカー、警察の仕事配置変更。
- GPS型画面端ナビ、音声チュートリアル、モーダル追加。

## 10. リスクと対策

| リスク | 対策 |
| --- | --- |
| 炎と既存小物が重なり対象を読みづらい | targetをsolidから離し、画像で赤橙黄の輪郭を確認する。 |
| route終端で消防車が対象へ向かない | 最後の2点の同Z・東側・西向き順序をunit testで固定する。 |
| 旧仕事IDがテストや音声fixtureへ残る | `rg`で参照残りを確認し、仕事変更のconsumer-visible結果を更新する。 |
| E2Eだけが秘密座標を使う | 描画中の`visualLayout.routeMarkers`と`landmarks.fireSprayTarget`から接近計画を作る。 |
