# 積み木の衝突位置カバレッジ設計

## 目的

GitHub Issue #3「積み木」に対し、同じ積み木へ十分な勢いで車両を押し当てた場合、当たる横位置に依存せず破壊できるようにする。既存の玩具らしい6主破片、補助chip、5秒復元、非車両除外は維持する。

## 再現結果と原因

- 黄色い積み木の東面を横位置 `-2.15 / -1.05 / 0 / 1.05 / 2.15` の5点から、画面スワイプと同じ入力で狙う。
- `+2.15` では回転したCuboidの角へ先に触れ、最初の `onCollisionEnter` 時点の車両前step速度が `2.9209` だった。
- 押し続けると公開telemetry上の前step速度は `3.5569` まで上がるが、`onCollisionEnter` は一度しか発火しないため、閾値 `4` を再評価できない。
- colliderの大きさや破壊閾値ではなく、「接触開始だけを判定するイベント選択」が位置依存の原因である。

## 世界観辞書

見た目は変更しない。木製の箱庭、色面で区切った地区、赤黄青緑の玩具積み木、角張った6主破片と小さなchipという既存語彙を維持する。今回の変更は見えない接触判定だけに限定する。

## 設計

`BreakableBlockPlaza` の積み木RigidBodyへ `onContactForce` を追加し、Rapierが接触を解決しているframeでも車両前step速度を再評価する。

- `onCollisionEnter` は実接触回数と車両接触回数を従来どおり一度だけ記録する。
- `onContactForce` は毎frame発火しても回数を増やさず、専用refで現在の車両 `onCollisionEnter` が記録された積み木だけを再評価する。`onCollisionExit` と破壊時にrefを解除し、復元後へ持ち越さない。
- phaseが `intact` の間だけ評価し、`registerBlockImpact` の既存閾値と冪等性を使う。
- 破壊後の固定body無効化、6主破片の固定pool有効化、chip burstは共通処理へまとめ、二重timerを作らない。
- collider拡大、速度閾値低下、車両加速変更は行わない。

## 受け入れ条件

- [x] 黄色い積み木の5横位置すべてで、実スワイプ入力による1回の車両接触から破壊できる。
- [x] 各位置の破壊速度が `4` 以上で、6主破片だけが有効になる。
- [x] 接触中の再評価で `impactCount` と `vehicleImpactCount` がframe数ぶん増えない。
- [x] 既存unit、build、全Voxel Game E2Eが成功する。
- [x] 代表スクリーンショットで積み木、破片、HUDに見切れ・重なり・意図しない見た目変更がない。
- [ ] GitHub Pages公開版で5位置検証とconsole error 0を確認する。

ローカル最終結果は48 files／470 tests、production build成功、5位置の破壊速度`4.206〜4.481`、各`vehicleImpactCount=1`、対象6主破片、ブラウザエラー0だった。canonical全E2Eでは3 viewport、4色破壊、40 collider、水流、仕事、HUD実寸が成功した。10枚の衝突前後画像を原寸目視し、意図した黄色積み木から6片への変化以外に重なり・見切れ・外観差分がないことを確認した。

## 非対象

- 積み木の数、配置、色、サイズ、破片形状の変更。
- 車両速度、操舵、カメラ、仕事進行の変更。
- 衝突閾値 `4` や復元時間 `5,000ms` の緩和。
- 助走不足で実速度が `4` へ届かない低速押しによる破壊。

## リスクと対策

- `onContactForce` が毎frame発火する: 接触回数はenter時だけ更新し、phase gateとruntimeの冪等判定で破壊処理を一度にする。
- contact forceがenterより先に届く: 車両enter記録がないframeは継続判定を無視し、次frameから評価する。
- 破片や他のbodyが押して壊す: 既存の質量・車両telemetry照合を両イベントで共用する。

## 性能目標

- 既存4つの固定積み木以外へbody、collider、meshを追加しない。
- 接触中だけO(1)の速度・車両照合を行い、毎frameのReact state更新や永続slotを増やさない。
- production bundleの既存予算と全E2Eのframe progressionを維持する。
