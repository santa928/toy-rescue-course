# 消防・ブルドーザー おしごと導線修正 設計

**日付:** 2026-08-03

**状態:** 実装済み・消防REQ-092/093/096は幼児視認性設計で一部置換

> 2026-08-03の実プレイ確認で、建物北面へ対象を置く方針そのものが3歳児には難しいと判明した。消防に関する最新要件は`2026-08-03-preschool-mission-visibility-design.md`を正とする。ブルドーザーREQ-094/095はこの文書どおり維持する。

## 1. 目的

Issue #1で追加した仕事札とミニマップだけでは残った、次の2つのプレイ上の詰まりを解消する。

- 消防車の窓火災で、地面の道しるべが建物の南側で終わり、北面の火が建物に隠れる。
- ブルドーザーで、操作ボタンを押しながら走る必要と、3個のうち次に片付けるがれきが伝わらない。

消火判定、ブレード接触判定、自由走行、自由破壊、仕事抽選、帰庫再開は変更しない。

## 2. 世界観辞書

共通語彙は「木の机、玩具の街、黄色い工事標識、赤橙黄の玩具の炎」とする。消防の目的地は黄色い積み木の下向き矢印、ブルドーザーの対象は黄色い積み木の四角い囲いとして表す。写実的なGPS矢印、発光テクスチャ、画面中央を覆うチュートリアル、常時点滅するDOM警告は使わない。

主要オブジェクトとのアンカーは次のとおりとする。

- 消防矢印は現在の`sprayTarget`にアンカーし、最上部を火災建物の屋根より高くする。
- ブルドーザー囲いは定義順で最初の未完了がれきにアンカーし、片付け成功時に次対象へ移る。
- 既存HUDは画面上中央、ミニマップは右上ボタン列の下という既存アンカーを維持する。

## 3. 検討案

### A. 文言と地面ルートだけ直す

描画コストは最小だが、建物やカラーブロックに対象が隠れる問題は残る。

### B. ルート、文言、既存batch内の立体目印を直す（採用）

消防ルートを建物の東から北へ回し、消防は下向き矢印、ブルドーザーは対象囲いを追加する。どちらも既存の黄色い`InstancedMesh`へ固定slotとして統合し、draw callを増やさない。画面内案内と実世界の対象が同じ位置を示すため、幼児でも操作と目的を結び付けやすい。

### C. 画面端へGPS型ナビ矢印を追加する

遮蔽物越しでも強い一方、画面方向と世界方向の変換、画面端clamp、HUD安全余白が必要になる。玩具の箱庭よりカーナビに見えやすいため今回は採用しない。

## 5. 実装境界

### 消防ルートと目印

`vehicleJobs.ts`の窓火災12点を、中央道路6点、東道路3点、北道路3点へ組み直す。最終2点は同じX座標で北から南へ進み、車両前方が火を向くようにする。

`WaterAndFire.tsx`は既存の12 route boxと6 target beacon boxを別配列で生成し、描画時だけ1つの`guideBoxes`へ束ねる。`visualLayout.routeMarkers`は運転経路12点だけを公開し、`targetBeacon`は別フィールドで公開する。`routeCubeCount`の意味は変えず、`targetBeaconCubeCount`を追加する。

### ブルドーザー対象囲い

`bulldozerVfx.ts`の黄色いroute poolへ4固定slotを追加する。7 route slotは既存経路を維持し、4 target slotは未完了対象の周囲へ四角形を作る。`sourceIndex=-2`をtarget slotの内部識別に使い、telemetryではroute 7とtarget 4を別々に数え、実際に描画した囲いの中心も公開する。

成功条件は既存どおり、ブレード操作中、速度0.6以上、前面接触とする。判定値は緩和しない。

## 6. エラー処理と不変条件

- 窓火災の経路は12点、有限座標、東側迂回点、北側の最終点を必須とする。
- 未完了がれきがない場合は対象囲い4 slotをzero scale・地下位置へ隠す。
- 別車種選択中、成功演出中、route非表示中は対象目印も隠す。
- 既存配列とThree scratchを毎frame再生成しない。

## 7. 検証

- RED/GREEN unit: 窓火災の東→北経路、消防矢印6 voxel、ブルドーザー文言、未完了対象囲い4 voxelと次対象移動。
- Docker full Vitestとbudget付きproduction build。
- Docker Playwright: 消防車を2周し、実route telemetry由来の接近で2件目を完了する。
- Docker Playwright: ブルドーザーで対象囲い、ブレード押下中の片付け、次対象への移動、3個完了を確認する。
- Desktop 1280×720、Tablet 1024×768、Mobile landscape 844×390で画像を撮り、原寸目視する。
- `render_game_to_text`と画像で、対象座標、marker数、HUD文言、console／page／request errorを照合する。

## 8. 性能目標

- 追加draw call 0、Rapier body／collider 0、asset fetch 0。
- 消防は既存route batchへ6 instance追加、ブルドーザーは既存route batchへ4固定slot追加まで。
- 毎frame React state更新0、配列生成0、Three object生成0。
- 既存build budgetを維持する。

## 9. 非対象

- 消火時間、放水距離、火災座標、ブレード速度・接触半径の変更。
- 新しい仕事、チュートリアルモーダル、音声ナビ、回転／ズーム可能な地図。
- 自由破壊ブロックの削除や色変更。

## 10. リスクと対策

| リスク | 対策 |
| --- | --- |
| 消防矢印が火や建物を隠す | 火より上へ配置し、6個の小さいvoxelだけで下向き形状を作る。 |
| がれき囲いが通常ブロックと衝突して見える | 地面近くへ細い4辺だけを置き、物理判定を持たせない。 |
| marker追加でroute数の既存契約を壊す | routeとtargetのtelemetry数を分離し、route 12／7を維持する。 |
| E2Eだけが専用座標で成功する | 実際に描画されるroute telemetryから最終接近位置を導出する。 |
