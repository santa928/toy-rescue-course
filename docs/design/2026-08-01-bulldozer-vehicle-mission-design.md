# ブルドーザー車種縦切り 設計

## 目的

現在の消防車1台の72×72ボクセル箱庭へ、2台目の働く車としてブルドーザーを追加する。
中央車庫で停止中に車両を選び、消防車は消火、ブルドーザーは西の工事現場でがれきを
片付けられるようにする。自由走行と通常の積み木破壊は、どちらの車でも引き続き遊べる。

本設計は、複数車種へ広げられる最小の型付き基盤と、ブルドーザーの車体・専用アクション・
専用ミッションを、PC・タブレット・スマホで最初から最後まで遊べる縦切りとして完成させる。
ゲームオーバー、制限時間、報酬、機能解放は追加しない。

## アプローチ比較

### A. 車両registry＋仕事coordinator（採用）

車種ごとの静的情報を型付きregistryへ置き、消防と工事のruntimeは共通snapshot契約の背後で
分ける。既存の`VoxelGameRuntime`は消防仕事として利用し、ブルドーザー用runtimeを追加する。
coordinatorは選択車両、選択可否、現在の仕事snapshot、帰庫再開だけを管理する。

- 長所: 動作済みの消火・物理・VFXを最小変更で守れる。
- 長所: 車体、速度、質量、アクション文言、仕事を1つの車両IDから導出できる。
- 長所: 次の救急車、パトカー、ショベルカーを同じ境界へ追加できる。
- 短所: 消防runtimeと工事runtimeの内部状態は完全には共通化されない。

### B. 既存runtimeを汎用状態機械へ全面改修（不採用）

全仕事を単一のイベント／状態機械へ置き換える。最終形は整うが、消火時間、火の強度、帰庫、
積み木復元まで同時に触るため、2台目の価値と無関係な回帰範囲が大きすぎる。

### C. AppとSceneへ車種条件分岐を直接追加（不採用）

実装は最短だが、HUD、モデル、物理、VFX、telemetryへ別々の`if`が増える。
3台目で同期漏れが起きやすく、車両追加の基盤にならない。

## 世界観辞書

- 机: 暖かい明色の木製天板。世界全体を子どもの遊び机として見せる。
- 道路: 濃灰のボクセル道路、黄色い中央線、白い短い横断ライン。
- 消防車: 赤白、青い窓、黒いタイヤ、銀色ホース。役割は火を消すこと。
- ブルドーザー: 建設玩具らしい黄色、黒い履帯、濃灰の足回り、銀灰の幅広ブレード。
- 工事現場: 西地区の木色土台へ、黄黒ストライプの柵と茶・灰・黄のがれきを置く。
- がれき: 壊れる対象だと分かる大きめの3塊。一般の背景や建物と色・輪郭を分ける。
- ブレードアクション: ブレードが少し下がり、接触点から小さい四角い破片が弾ける。
- 道しるべ: 選択車両の仕事色を使う。消防は黄色、工事は橙黄色で区別する。
- HUD: 木製玩具のラベル感を保ち、仕事名と右ボタンだけを車種に合わせる。
- 文言: ひらがな中心で、命令より「〜しよう」の短い誘いにする。

背景、箱庭、HUD、ボタン、対象、文言、エフェクトはすべて「机上で働く玩具の車」という
同じ語彙に乗せる。ロゴ、フォトテクスチャ、写実的な土煙、丸いLEGOスタッドは追加しない。

## プレイフロー

### 初回と乗り換え

1. 消防車が中央車庫に停車した状態で始まる。
2. 車庫内かつ速度0.35以下なら、左上に2台の車両セレクターが表示される。
3. 「しょうぼうしゃ」「ブルドーザー」をタップまたはキーボードで選ぶ。
4. 選んだ車両が同じ安全な開始位置へ切り替わり、その車の仕事が`assigned`になる。
5. 車庫から出ると仕事が`active`になり、仕事地区への道しるべが表示される。
6. 車庫外または走行中はセレクターを操作不可にする。
7. 切り替え時に車体pose、速度、角速度、入力を安全にリセットする。
8. 新しい車種の専用仕事は最初から始め、通常積み木の状態は乗り換えに依存させない。

### ブルドーザー仕事

1. 上中央へ「こうじげんばへ いこう」を表示する。
2. 西地区へ近づくと「がれきを 3こ かたづけよう」へ切り替える。
3. 右の「ブレード」またはSpaceを押すと前面ブレードが作動する。
4. 作動中のブレードが近距離でがれきに触れ、車速0.6以上なら、その1塊が破片へ変わる。
5. 残数を`あと 2こ`、`あと 1こ`と表示する。
6. 3個すべて片付くと玩具の星が短時間出て、自由走行へ移る。
7. 車庫へ戻ると同じ車種の仕事が再配置され、もう一度遊べる。

速度条件は「勢いをつける技術」を要求するためではなく、停車したまま触れただけで消えないための
下限とする。位置合わせを要求する押し込みゾーン、制限時間、失敗判定は設けない。

## アーキテクチャ

```text
vehicleDefinitions.ts
  ├─ VehicleId
  ├─ visual / physics / action / mission definition
  └─ getVehicleDefinition(id)
          ↓
VehicleMissionCoordinator
  ├─ selectedVehicleId / canSwitch
  ├─ FireMissionRuntime (existing VoxelGameRuntime)
  └─ BulldozerMissionRuntime
          ↓
VoxelGameApp
  ├─ generic mission snapshot / selector / telemetry / primary action
          ↓
VoxelGameScene
  ├─ VehicleController keyed by vehicle id
  │    ├─ VoxelFireTruck
  │    └─ VoxelBulldozer
  ├─ WaterAndFire (fire mission only)
  ├─ BulldozerDebrisMission (bulldozer mission only)
  └─ shared World / BreakableBlockPlaza / Camera
```

### 車両定義

`VehicleId`は`'fire-truck' | 'bulldozer'`とする。定義には表示名、アクションlabel／aria-label、
仕事ID・目的地区、質量、最大速度相当、移動／停止／旋回応答、collider offset／scale、
描画boundsとvoxel batch上限を持たせる。registryは重複ID、非有限または0以下の物理値、
空の文言をpure validatorで拒否し、不正IDは消防車へ安全にフォールバックする。

消防車の現在値は変更せず定義へ移す。ブルドーザーは重く感じるが幼児が扱いにくくならない範囲で、
質量を消防車より大きく、応答を少し低くする。正確な値は既存値を基準にunitと実ブラウザで決める。

### 共通仕事snapshot

- `id`: `fire-rescue`または`debris-clearance`
- `vehicleId`
- `phase`: `assigned | active | celebrating | freeRoam`
- `destinationDistrict`
- `objectiveLabel`
- `progress`: `current / target`
- `routeVisible`

消防固有の火の強度や放水経路、工事固有のがれきslotは、それぞれのvisual telemetryへ残す。
共通UIが固有状態を推測しないよう、表示文言はsnapshotから導出するpure helperへ集約する。

### primary action

公開入力は`spray`を車種共通の`primaryAction`へ変更する。Spaceとタッチ右ボタンは
この1状態を更新する。`WaterAndFire`は消防車選択中だけ放水として読み、
`BulldozerDebrisMission`はブルドーザー選択中だけブレードとして読む。
切り替え時は押下中のpointerやkeyが残らないよう入力stateを初期化する。
古い`controls.spray`への依存は同一タスク内で参照残りを検査し、互換fieldを残さない。

## ブルドーザー造形

- 消防車と同じ`VoxelCell`／render planを使い、外部3Dアセットを追加しない。
- 消防車より短い全長と、前面ブレードによる広い全幅を持つ。
- 左右の黒い履帯、黄色い機関部、青灰の窓、小さな運転席、橙色回転灯を持つ。
- 銀灰のブレードは前方へ張り出し、接地面近くまで下げる。
- 800 voxel以下、7 palette batch以下、model-space bounds内を受け入れ上限とする。
- ブレード作動は別React stateにせず、refまたはframe値で小さく上下させる。

## 工事現場とがれき

西の積み木地区に、通常の4色積み木と重ならない3つの`bulldozerDebris` landmarkを追加する。
各がれきは一意ID、位置、色構成、当たり判定半径を持ち、map validatorで地区内・world内・
互いの最小間隔・通常積み木との非重複を検証する。

がれきの除去条件はpure helperへ分離する。

```text
selectedVehicleId === 'bulldozer'
&& primaryAction === true
&& speed >= 0.6
&& bladeCenterと未処理がれきのXZ距離 <= debrisRadius + bladeRadius
```

1 frameで複数を除去しない。破片は固定slot poolを使い、毎frameのReact state更新とgeometry生成を
避ける。がれき本体は色ごとの`InstancedMesh`最大3 draw call、破片も最大3 draw callを目標とする。
通常積み木の物理body、破壊threshold、復元timerは変更しない。

## HUDアンカーと操作

- 仕事表示: Canvas上中央。現在車種のobjectiveと進捗を表示する。
- 全画面: Canvas右上＋safe area。既存位置を維持する。
- 車両セレクター: Canvas左上＋safe area。車庫内・停止中だけ表示する。
- 運転スティック: Canvas左下＋safe area。
- primary action: Canvas右下＋safe area。車種ごとに色、文言、aria-labelを更新する。

車両セレクターは2つの実ボタンで、選択中を`aria-pressed="true"`にする。表示条件だけで
操作可否を表現せず、pure helperとevent handlerの両方で車庫・速度条件を守る。

844×390では、左上セレクターの右端を画面幅の42%以下、仕事表示・全画面・セレクターの
矩形間に8px以上の安全余白を置く。1024×768、1280×720でも、下部操作と車両、次の道しるべが
重ならないことを実画面で確認する。

## 状態遷移とエラー処理

- 車庫内でも速度0.35を超える切り替え要求は無視する。
- 車庫外の切り替え要求は無視し、現在車両と仕事を変更しない。
- 乗り換え中はsceneを車両IDでkey再生成し、古いrigid body refを使わない。
- 無効な車両IDは消防車へフォールバックし、例外でゲーム全体を停止しない。
- がれきref未準備のframeは接触判定を行わず、次frameへ送る。
- 同じがれきへの重複イベントはruntimeが冪等に無視する。
- 仕事完了後のブレードは自由遊びの演出だけを続け、進捗を再加算しない。
- 帰庫再開時に、がれきslotと破片poolを同期して初期化する。

## テスト方針

### Unit（実装より先に追加）

- registryが2車種を一意に持ち、不正な定義を拒否する。
- 消防車の既存物理値とboundsが移行前と一致する。
- ブルドーザーが800 voxel以下、7 batch以下、左右対称でbounds内に収まる。
- 車庫内かつ速度0.35以下だけ乗り換え可能になる。
- primary actionがkeyboard／touchから同じcommandになる。
- がれき除去条件が車種、アクション、速度、距離の各gateを守る。
- 同じがれきの重複除去が進捗を増やさない。
- 3個で`celebrating`、成功時間後に`freeRoam`、帰庫で`assigned`へ戻る。
- mapが3個のがれきと工事道しるべを一意かつ西地区内に保持する。
- 仕事文言が車種、phase、進捗と一致する。

### Integration

- controllerが車両定義からmodel、collider、物理値を選ぶ。
- 消防車選択中だけ放水、ブルドーザー選択中だけがれき片付けが反応する。
- 通常積み木が両車で動作し、乗り換えでresetされない。
- 乗り換え時にpose、速度、入力、仕事が同期する。
- telemetryのvehicle、mission、landmark、visual actualが描画と一致する。

### E2E

- PC: 車庫でブルドーザーへ切り替え、WASD＋Spaceで3個を片付け、自由走行へ入る。
- Touch: セレクター、左スティック、右「ブレード」で同じ仕事を完遂する。
- 回帰: 消防車へ戻り、見える炎を放水で消して自由走行へ入る。
- 回帰: 両車で通常積み木を壊せる。
- 不可条件: 車庫外と走行中の乗り換えが無視される。
- 1280×720、1024×768、844×390で矩形、safe area、操作阻害を検証する。
- スクリーンショットを目視し、車種差、対象、道しるべ、HUD文言を確認する。
- console error、pageerror、NaN、world外、stuckを0件にする。

## 非対象

- 色付きプール、色付きシャワー、一時色競合の解決。
- 救急車、パトカー、ショベルカー。
- 複数火災、ランダム仕事、追加マップ地区。
- 効果音、BGM、サイレン、振動。
- ゲームオーバー、制限時間、評価、通貨、機能解放、保存、進行管理。
- 写実的な土煙、流体、車体損傷、精密サスペンション、マルチプレイ。
- 72×72で性能目標を満たす限り、chunk streamingとLOD。

## 性能目標

- ブルドーザー本体は800 voxel以下、7 draw call以下。
- 工事がれき本体は3 draw call以下、破片poolも3 draw call以下。
- 乗り換えや仕事進捗の離散イベント以外でReact stateを毎frame更新しない。
- loop内でgeometry、material、大きな配列を毎frame生成しない。
- physical GPUで中央値55fps以上、p10 45fps以上を目標とする。
- 未達時はbatch、shadow、生成頻度を調整し、map拡張やchunk化へ先走らない。

## リスクと対策

| リスク | 対策 |
| --- | --- |
| 車種共通化で消防車の消火契約が変わる | runtimeを全面改修せずadapter境界で温存し、既存E2Eを必須回帰にする。 |
| がれき除去が積み木破壊と二重反応する | 配置を分離し、専用ID・専用runtime・1 frame 1件の冪等処理にする。 |
| 車両切り替えで古いphysics refや入力が残る | 車両IDでcontrollerをkey再生成し、pose・速度・入力を同時resetする。 |
| 小画面でセレクターが仕事表示へ重なる | 左上アンカー、実寸矩形helper、844×390の数値検証を先に固定する。 |
| 2車種化で条件分岐が散らばる | vehicle registryとmission coordinatorへ選択を集約する。 |
| draw call増加で性能が落ちる | 車体・がれき・破片をpalette別InstancedMeshへまとめ、上限testを持つ。 |
