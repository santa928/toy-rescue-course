# ボクセル働く車ゲーム — 消防車デザイン・スパイク設計

## 目的

本開発へ入る前に、純ボクセル表現の消防車を React Three Fiber / Three.js で1台だけ実装し、見た目と描画方式を実ブラウザで評価する。

このスパイクでは既存ゲームを置き換えない。既存ゲームと同じリポジトリに独立した展示ページを追加し、消防車のデザイン承認後にのみ運転、物理、箱庭、ミッションの設計へ進む。

## 採用方針

既存の React、TypeScript、Vite、Docker、React Three Fiber、Three.js の基盤は再利用する。密結合した既存ゲーム本体は直接改造せず、新設計を並行して構築する。

最初の実装単位は `vehicle-lab.html` とし、既存の `index.html` から独立して開ける Vite の複数エントリ構成にする。

## 世界観辞書

- 車両: 同じ基準グリッドに揃えた小さな立方体のみで構成する。
- 輪郭: 遠目でも消防車と分かる、短く太い幼児玩具の比率にする。
- 色: 赤い車体、白いライン、黒い窓とタイヤ、銀色の梯子、青い警光灯を使う。
- 質感: マットな玩具プラスチック。角丸形状や写実的な金属反射は使わない。
- ディテール: 梯子、側面シャッター、ライト、バンパーまでを表現し、文字とロゴは付けない。
- 展示台: 暖色の木製台とニュートラルな背景を使い、車体の色と輪郭を読みやすくする。
- 将来の箱庭: 車庫、道路脇の積み木、瓦礫も同じボクセル寸法と色語彙へ揃える。

## アーキテクチャ

### ファイル境界

- `vehicle-lab.html`: 消防車展示ページの HTML エントリ。
- `src/vehicle-lab/main.tsx`: React 起動処理。
- `src/vehicle-lab/VehicleLabApp.tsx`: Canvas、案内、エラー境界を構成する。
- `src/vehicle-lab/scene/VehicleShowroom.tsx`: カメラ、ライト、展示台、操作を担当する。
- `src/vehicle-lab/model/fireTruckVoxels.ts`: 消防車のボクセル座標とパレットIDを定義する。
- `src/vehicle-lab/model/voxelModel.ts`: 検証、境界計算、色別グループ化を行う pure module。
- `src/vehicle-lab/scene/VoxelFireTruck.tsx`: 色ごとの `InstancedMesh` を生成する。
- `src/test/voxelModel.test.ts`: 座標データと pure helper を検証する。

既存の `src/App.tsx`、`src/scene/ToyRescueScene.tsx`、`src/scene/VehicleModel.tsx` は変更しない。

### データモデル

各ボクセルは整数のグリッド座標とパレットIDだけを持つ。

```ts
interface VoxelCell {
  readonly x: number;
  readonly y: number;
  readonly z: number;
  readonly paletteId: FireTruckPaletteId;
}
```

モデル定義は次を満たす。

- 座標が整数である。
- 同じ座標が重複しない。
- パレットIDが定義済みである。
- 800セル以下である。
- 原点を基準に車体が中央配置される。

### 描画フロー

1. `fireTruckVoxels.ts` からボクセル定義を読み込む。
2. pure helper で座標、重複、パレット、境界を検証する。
3. パレットIDごとにセルをグループ化する。
4. 共通の `boxGeometry` と色別 `InstancedMesh` を作る。
5. 各セルのグリッド座標を instance matrix へ変換する。
6. `VehicleShowroom` が Orthographic Camera、ライト、展示台、操作を重ねる。

## 操作と画面

- マウスドラッグまたは1本指ドラッグで車体の周囲を回転する。
- マウスホイールまたはピンチで拡大・縮小する。
- 初期状態ではゆっくり自動回転し、ユーザー操作後は停止する。
- ズーム範囲を制限し、車体の内部や画面外へ入り込まないようにする。
- 文字案内は短い日本語にし、3D表示を塞がない安全余白へ配置する。

## エラー処理

- 重複座標、非整数座標、未知のパレットID、上限超過は開発時に明示的な例外にする。
- モデル構築に失敗した場合は空の Canvas にせず、日本語のエラーパネルを表示する。
- WebGL が利用できない場合は、対応ブラウザで開き直す案内を表示する。
- エラー詳細はコンソールへ残し、幼児向け画面には技術情報を表示しない。

## テストと検証

### 自動テスト

- 座標がすべて整数である。
- 重複座標がない。
- パレットIDがすべて有効である。
- ボクセル数が800以下である。
- 境界計算が既知の最小・最大座標を返す。
- 色別グループ数が draw call 上限を超えない。

### ブラウザ検証

開発環境、テスト、ビルド、Playwright は Docker 内で実行する。

- Desktop: 1280×720。
- Tablet landscape: 1024×768。
- Mobile landscape: 844×390。
- 正面、左側面、背面、右側面のスクリーンショットを取得する。
- 各画像を目視し、シルエット、欠損、はみ出し、案内文との重なりを確認する。
- 代表 viewport ごとに Canvas と案内UIの境界を数値でも確認する。
- `renderer.info.render.calls` と実セル数を記録する。

## 受け入れ条件

- 選定した純ボクセル案のシルエット、配色、梯子、警光灯が再現されている。
- 前後左右と上方向から見ても消防車と認識できる。
- マウスとタッチの両方で回転・ズームできる。
- 既存ゲームと独立したURLで開ける。
- 3種類の代表 viewport で車体や操作案内が切れない。
- Docker 内でテスト、型チェック、ビルドが成功する。
- ブラウザコンソールにアプリ由来のエラーがない。

## 非対象

- 運転、車輪アニメーション、物理演算。
- 放水、サイレン、警光灯アニメーション。
- 箱庭、車庫、ミッション、ゲームHUD。
- 消防車以外の車両。
- 最終版の質感、効果音、演出調整。

## リスクと対策

- コンセプト画像が細かすぎる: 小画面で読める輪郭を優先し、装飾ボクセルを省く。
- ボクセル数と draw call が増える: 色別の `InstancedMesh` と共通 geometry を使う。
- 正面だけ似て側面と背面が弱くなる: 4方向の固定カメラ画像で確認する。
- 純ボクセルが硬く冷たい印象になる: 車体比率、色、暖色の展示台、柔らかい照明で幼児玩具らしさを補う。
- 既存ゲームへ影響する: 独立エントリと専用ディレクトリに閉じ込める。

## 性能目標

- 消防車は800ボクセル以下。
- 描画は10 draw call以下。
- Desktopは60fps、Mobileは30fps以上。
- 展示ページでは不要な物理エンジンを読み込まない。
